## 目标与定位

服务同一个人的多设备使用：Android 整理元件、Windows 处理资料与项目、Web 提供包括 iPhone / iPad 在内的在线访问入口。

本次只补齐三个主题：**元件照片同步、BOM 预设同步、同步状态提示**。继续保持 Android / Windows 本地优先、离线可用、按需连接自托管服务的使用方式。

## 待办一：元件照片同步

- [ ] 将用户保存的元件照片及其与元件的关联纳入可选同步，让 Android、Windows、Web 能显示同一张已同步照片。
- [ ] 保留现有本地照片；升级后可逐步同步，不要求重新拍摄或重新导入库存。
- [ ] 本地保存照片不等待服务器；未启用同步或暂时离线时，仍能使用本地可用的照片。
- [ ] 区分无照片、待上传、待下载、传输失败与本地可用等情况；缺图或下载失败不阻塞库存查询和出入库。
- [ ] 处理重复重试、取消、断网和进程中断：已完成内容不反复创建，未完成内容可恢复或重试；不预先要求复杂分片传输。
- [ ] 明确替换、删除和多设备冲突的处理方式；不能把“本机还没下载”误认为“用户删除了照片”。
- [ ] 区分原始照片、下载缓存和临时文件，提供缓存清理并淘汰无效临时资源；清缓存不应删除唯一的未上传原图。
- [ ] 沿用账户和元件归属边界；官方商品图片地址与用户本地照片的关系、备份覆盖范围按新结构明确。

验收结果：Android 保存照片并同步后，Windows 和 Web 可看到；设备离线时仍可查看本地已有照片；一次图片传输失败不会被显示为全部同步完成。

## 共同实施边界

1. **保留本地离线使用。** 原生端库存写入继续先落本地；无需服务器也能使用已有功能。图片传输失败不应阻断独立的库存操作。
2. **保护现有数据。** 正确迁移照片、预设及同步关联；不要求清库、重新安装或重新录入作为正常升级步骤。
3. **面向个人。** 保留既有账户隔离，不新增共享工作室、成员角色、审批或多人生产体系。
4. **沿用现有架构。** 复用重构后的服务与存储职责；先选简单、可重试的操作单元，不让网络传输占用长数据库事务。
5. **恢复行为明确。** 空状态、部分完成、重试、取消、中断和冲突都必须有处理方式；优先保留已完成结果与未上传数据。
6. **兼容边界由真实需求决定。** 若同步协议或 schema 变化影响现有安装，明确升级顺序与诊断；不得静默丢弃新数据，也不提前设计无需求的兼容层。
7. **发布继续走 dev。** 实施完成后按项目规则交付开发版；正式发布仍由用户决定，不因 CI 成功推进 Docker 稳定标签。

## 2026-10-22 实施前代码复核与建议顺序（历史）

以下为 dev18 实施前分析快照，其中“预设尚不互通”和“同步结果仅覆盖库存”已由文末实现记录更新，不再代表当前状态。该次分析没有启动开发。Windows 核心链路和 Android 核心 Repository/ViewModel 已完成前述模块化阶段，不把这视为全仓重构或全功能验收完成。

### 仍存在的缺口

- **照片文件未同步。** 两个原生端有本地图片存储和 Excel 图片备份，库存 description 能携带本地图片标记，但 `/sync/push`、`/sync/pull` 没有传输图片内容。另一设备拿到标记不等于拿到照片。应区分用户原图、已下载副本与供应商公开图片地址。
- **预设尚不互通。** Android `data/bom/BomPresetStore.kt` 的本地预设有稳定 ID、原始需求和 canonical key；Windows `Services/Bom/BomPresetStore.cs` 按名称覆盖，选择/跳过项按行号保存。先定义共同的预设 ID 与条目 ID，再迁移旧文件，不能把行号直接当 Android 的需求键。
- **同步结果仅覆盖库存。** Android 的同步偏好与 Windows 的 `SyncCoordinator` 已有库存状态来源，服务端也有审计和冲突记录；尚无照片和预设的持久进度。新增数据类型后必须显示部分完成，不能继续用一次库存交换的成功代表全部成功。

### 建议小步实施

1. **先明确数据契约与旧资料迁移。** 约定预设稳定标识、修改/删除记录、照片关联与账户边界；保留现有库存协议和本地文件，列出受影响的备份范围。仅增加这三类数据实际需要的状态，不先造通用任务平台。
2. **先交付 BOM 预设同步的 dev。** 数据为有界 JSON，先做 Android ↔ 服务端 ↔ Windows；旧预设逐个纳入同步，重复同步不新建重复项目。跨端打开后用当前本地库存重新计算，保留人工选择与跳过项，绝不自动扣料。Web 先提供只读列表/详情。
3. **再交付照片同步的 dev。** 本地保存立即成功，网络传输在独立操作中完成；失败可重试，元件库存同步不受图片失败阻塞。首次只需整文件上传/下载，无证据不加分片。删除/替换与“本地未下载”分开；清缓存不删除唯一未上传原图。
4. **随各步完善统一状态。** 在既有同步协调器中分别记录库存、预设、照片结果及待处理项，汇总为完成/部分完成/失败，并提供对应重试。重启后能恢复可信状态，Web 保存成功不代表离线原生端已接收。

以上为实施前建议；后续照片工作仍需单独启动。各步按实际执行分别记录构建、直接测试、原生实机和 Web 浏览器结果。

## 2026-10-22 dev18 已实施范围与剩余限制

- **BOM 预设互通已实施。** 两端使用 version 2 原子 JSON，旧格式成功解码后备份迁移；稳定预设/需求 ID、来源行与工作表、项目与套数、人工选择及跳过项通过独立 `/sync/bom-presets` 交换。服务端沿用账户隔离数据库；删除保留墓碑。按 UTC updated_at 执行整条记录 LWW，同时间服务端胜出，不做字段合并或人工冲突合并。请求期间的新本地编辑保留到下轮同步。
- **配套件已实施。** Android / Windows 可从现有库存选件或带入 BOM 预设，显示正数需求与自动库位计划；仅明确确认后复用 BOM 原子提交器和 releaseId 扣料。打开、同步、查看预设不扣库存，也不预占库存。草稿仅保留当前会话，不承诺杀进程或应用结束后恢复；没有跨设备预占和统一生产批次账本。
- **Web 只读已实施。** `/bom-presets` 显示当前账户列表与需求详情、每套/总需求、选择、跳过和参考位号，支持中英文、分页及失败重试；不提供预设修改或 Web 配套扣料，也不显示未经库存复核的“可用量”。
- **同步部分完成已有窄范围处理。** 库存成功而预设不受支持/失败时保留库存成功结果和本地预设，提示部分完成；旧服务端缺少能力字段或接口不会清空本地资料。照片仍只在本地和既有 Excel 图片备份内，不包含在此次同步完成的范围。

本次直接验收：真实 Windows 服务 → 隔离 FastAPI → Android 手机 → Windows 往返成功，manual 选择和 skip 保留。手机明确确认一次仅扣 6 和 2，重试没有额外扣减；Windows 删除预设后手机列表清空，库存仍为 14/18。Web 实际浏览器核对列表、详情、每套 3 × 2 = 6、明确未匹配、跳过与中英文切换。构建与协议最小测试分别记录，不将其等同于全部 UI 或异常恢复验收。

照片同步继续延期。上方完整同步状态、照片失败重试、进程重启恢复等未完成条目保持待办；现有 LWW 行为不能被描述为已经提供人工冲突处理。库存 Excel 备份范围未扩大为预设备份，预设独立文件仍应单独保护。
